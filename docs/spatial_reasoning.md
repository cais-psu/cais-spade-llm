# Spatial Reasoning for Multi-Robot Recovery

## Overview

This document describes the workspace boundary and staging area system that enables intelligent spatial reasoning during online replanning and recovery scenarios.

## Key Components

### 1. Workspace Boundaries

Each robot now has explicit Cartesian workspace boundaries defined in its configuration:

**Location**: `cais_spade_llm/initialization/resources/robot_*.json`

```json
"workspace_boundaries": {
  "type": "rectangular",
  "x_range": [-150, 650],    // mm in robot base frame
  "y_range": [-550, 100],    // mm in robot base frame
  "z_range": [0, 600],       // mm in robot base frame
  "units": "mm",
  "description": "Cartesian workspace boundaries in robot base frame"
}
```

**Robot-Specific Workspaces**:
- **xArm6**: x: [-150, 650], y: [-550, 100], z: [0, 600] mm
- **UR5e**: x: [100, 900], y: [-450, 200], z: [0, 600] mm

These boundaries reflect each robot's physical reach and are used by the LLM to determine which robot can access a particular location.

### 2. Staging Areas

Staging areas are predefined locations where robots can temporarily place parts for handoff or recovery:

```json
"staging_areas": {
  "staging_zone_1": {
    "x": 200,
    "y": -250,
    "z": 172,
    "description": "Primary staging area for xArm6, reachable by UR5e for recovery",
    "accessible_by": ["xarm6", "ur5e"]
  },
  "staging_zone_neutral": {
    "x": 300,
    "y": -150,
    "z": 172,
    "description": "Shared neutral zone between both robots",
    "accessible_by": ["xarm6", "ur5e"]
  }
}
```

**Defined Staging Zones**:
- `staging_zone_1`: xArm6's primary staging (accessible by both)
- `staging_zone_2`: UR5e's primary staging (accessible by both)
- `staging_zone_neutral`: Shared handoff zone (accessible by both)

### 3. State-Based Function Composition

The tools catalog includes state transition information for each function, enabling automatic multi-step sequencing:

**State Transitions** (from `tools.json`):
```json
{
  "function": "pick_part",
  "function_owner_agent": "xarm6",
  "in_state": "printed",
  "out_state": "picked"
},
{
  "function": "move_loaded_to_destination",
  "function_owner_agent": "xarm6",
  "in_state": "picked",
  "out_state": "positioned"
},
{
  "function": "place_part",
  "function_owner_agent": "xarm6",
  "in_state": "positioned",
  "out_state": "placed"
}
```

**Function Chaining**:
The LLM can compose multi-step sequences by matching `out_state` → `in_state`:
- pick_part (printed → **picked**) → move_loaded (**picked** → **positioned**) → place_part (**positioned** → placed)

This enables **compositional reasoning** without hardcoded sequences.

### 4. Integration with Replanning

The workspace boundaries and staging areas are automatically included in the LLM's context during online replanning through the `static_capabilities` field.

**Updated**: `cais_spade_llm/prompts.py` - `REPLAN_ONLINE_INSTRUCTIONS`

Added section: **"COMPOSITIONAL RECOVERY WITH SPATIAL REASONING"**

This guides the LLM to:
1. **Chain functions** using state transitions (in_state/out_state)
2. **Check workspace boundaries** to select the appropriate robot
3. **Use staging areas** for compositional recovery
4. **Prefer existing primitives** (`pick_part`, `place_part`) over new functions
5. **Verify robot capabilities** using function_owner_agent field

## Example Recovery Scenario

**Situation**: xArm6 fails to place a Spring Guide (SG), leaving it at coordinates (500, -100, 172) which is outside xArm6's workspace but inside UR5e's workspace. UR5e is currently holding a Motor Connector Plate (MCP).

**LLM Reasoning Process**:
1. **State Check**: UR5e has out_state="picked" (holding MCP)
2. **Spatial Check**: SG at (500, -100, 172) is in UR5e's x_range:[100,900] ✓, not xArm6's x_range:[-150,650] ✗
3. **Capability Check**: Both robots have `pick_part` and `place_part` per function_owner_agent
4. **Composition Strategy**: UR5e must first place_part (MCP) to reach in_state for pick_part

**Recovery Strategy** (generated by LLM with state-based + spatial reasoning):

```json
[
  {
    "id": "UR5E_STAGE_MCP",
    "function_name": "place_part",
    "params": {
      "part_name": "MCP",
      "location": "staging_zone_2"
    },
    "resource_jid": "ur5e@localhost",
    "change_reason": "INSERTION: UR5e stages current part (state: picked→placed) to free gripper"
  },
  {
    "id": "UR5E_RECOVER_SG",
    "function_name": "pick_part",
    "params": {
      "part_name": "SG",
      "location": {"x": 500, "y": -100, "z": 172}
    },
    "resource_jid": "ur5e@localhost",
    "predecessors": ["UR5E_STAGE_MCP"],
    "change_reason": "INSERTION: UR5e selected (SG in workspace x:[100,900]) - state: printed→picked"
  },
  {
    "id": "UR5E_TRANSFER_TO_XARM_ZONE",
    "function_name": "place_part",
    "params": {
      "part_name": "SG",
      "location": "staging_zone_neutral"
    },
    "resource_jid": "ur5e@localhost",
    "predecessors": ["UR5E_RECOVER_SG"],
    "change_reason": "INSERTION: Stage in neutral zone (state: picked→placed) for xArm6 to access"
  }
]
```

## Benefits

1. **State-Based Composition**: LLM chains functions by matching state transitions (in_state/out_state), enabling novel multi-step sequences
2. **Formal Spatial Reasoning**: LLM makes geometrically valid robot selections based on workspace constraints
3. **Compositional Recovery**: Reuses existing primitives (`pick_part`, `place_part`) rather than requiring specialized functions
4. **Explicit Handoff Zones**: Staging areas provide safe, known locations for multi-robot coordination
5. **Paper Contribution**: Demonstrates intelligent compositional reasoning and spatial awareness in LLM-based multi-agent planning
