# CAIS-SPADE ROS2 Setup

This directory contains the project-owned ROS2 package for the xArm6, UR5e,
Gazebo, MoveIt, hardware, and digital twin runtime.

Use the root [README](../README.md) for the complete application installation.
Use this guide when ROS2 Humble is already installed and you want to prepare or
understand the ROS2 workspace.

## Why `~/ros2_ws` Exists

ROS2 discovers packages through installed workspace indexes. The source files in
this repository are not discoverable through `ros2 launch` until `colcon` builds
and installs them.

The current UI sources these environments before every managed ROS2 command:

```bash
source /opt/ros/humble/setup.bash
source ~/ros2_ws/install/setup.bash
```

Therefore:

- Python-only planning and `dry_run` can work without `~/ros2_ws`.
- Gazebo, MoveIt, RViz, hardware ROS2 control, and the digital twin require it.
- `~/ros2_ws` is generated build/runtime infrastructure; it is not another
  project to edit manually.

## Source and Workspace Layout

```text
cais-spade-llm/
└── ros2/
    ├── cais_lab_robotics/          # tracked project ROS2 package
    │   ├── package.xml
    │   ├── CMakeLists.txt
    │   ├── launch/
    │   ├── config/
    │   ├── worlds/
    │   ├── models/
    │   ├── cad_models/
    │   ├── rviz/
    │   ├── scripts/
    │   └── sensor/
    ├── docs/
    └── third_party/

~/ros2_ws/
├── src/
│   ├── cais_lab_robotics -> cais-spade-llm/ros2/cais_lab_robotics/
│   ├── xarm_ros2/
│   ├── OnRobot_ROS2_Description/
│   └── IFRA_LinkAttacher/
├── build/                          # generated by colcon
├── log/                            # generated by colcon
└── install/                        # generated package index and installed assets
```

`cais_lab_robotics` owns the CAIS launch files, worlds, controllers, RViz files,
models, sensor node, and synchronization scripts. Upstream packages keep their
existing names. In particular, `xarm_gazebo` remains installed because it
provides xArm Gazebo support, including the mimic-joint plugin; it does not hold
CAIS project files.

## 1. Install ROS2 Dependencies

Use Ubuntu 22.04 and ROS2 Humble. For a new WSL/Ubuntu installation, first follow
[wsl_ubuntu22_ros2_humble_setup.md](docs/wsl_ubuntu22_ros2_humble_setup.md).

```bash
sudo apt update
sudo apt install -y \
  ros-humble-desktop \
  python3-colcon-common-extensions \
  python3-rosdep \
  ros-humble-moveit \
  ros-humble-gazebo-ros-pkgs \
  ros-humble-gazebo-ros2-control \
  ros-humble-ur-description \
  ros-humble-ur-moveit-config \
  ros-humble-controller-manager \
  ros-humble-joint-state-broadcaster \
  ros-humble-joint-trajectory-controller \
  ros-humble-xacro \
  ros-humble-robot-state-publisher
```

Do not run raw ROS2 or Gazebo commands from the Poetry virtual environment.

## 2. Clone CAIS-SPADE-LLM

```bash
mkdir -p ~/projects
cd ~/projects
git clone <CAIS-SPADE-LLM-REPOSITORY-URL> cais-spade-llm
cd cais-spade-llm
```

If the repository is already cloned, continue from its root directory.

## 3. Create and Build the ROS2 Workspace

```bash
make bootstrap-gazebo
```

This single command:

1. Creates or reuses `~/ros2_ws`.
2. Clones `xarm_ros2`, `OnRobot_ROS2_Description`, and `IFRA_LinkAttacher` when
   they are missing.
3. Registers `ros2/cais_lab_robotics` as
   `~/ros2_ws/src/cais_lab_robotics` through a source symlink.
4. Copies only the maintained IFRA `gazebo_link_attacher.cpp` patch into the
   upstream IFRA source tree.
5. Builds the workspace with `colcon`.

The first build can take 15–30 minutes. Do not separately clone the upstream
repositories or run another full build during initial setup; bootstrap already
does both.

## 4. Source and Verify

Use a new terminal without an active Poetry virtual environment:

```bash
deactivate 2>/dev/null || true
source /opt/ros/humble/setup.bash
source ~/ros2_ws/install/setup.bash

ros2 pkg prefix cais_lab_robotics
ros2 pkg prefix xarm_gazebo
ros2 pkg prefix xarm_description
ros2 pkg prefix ur_description
ros2 pkg prefix ur_moveit_config
ros2 pkg prefix onrobot_description
ros2 pkg prefix linkattacher_msgs
ros2 pkg prefix ros2_linkattacher
```

`cais_lab_robotics`, xArm, OnRobot, and IFRA packages should resolve under
`~/ros2_ws/install`. The apt-installed UR packages should resolve under
`/opt/ros/humble`.

## 5. Launch a Simulation

UR5e with RG2:

```bash
ros2 launch cais_lab_robotics ur5e_rg2_moveit_gazebo.launch.py
```

xArm6 with xArm gripper:

```bash
ros2 launch cais_lab_robotics xarm6_moveit_single_gazebo.launch.py
```

Dual robots:

```bash
ros2 launch cais_lab_robotics dual_moveit_gazebo.launch.py
```

All dual-robot simulation modes use `cais_lab_robotics/worlds/table.world`.

## Safe Edit and Rebuild Workflow

1. Edit files under this repository's `ros2/cais_lab_robotics/` directory.
2. Run `make bootstrap-gazebo`.
3. Source `~/ros2_ws/install/setup.bash` in a new ROS terminal.
4. Test the installed package.

Do not edit `~/ros2_ws/build` or `~/ros2_ws/install`. Do not copy CAIS files into
`xarm_gazebo`.

## Troubleshooting

| Problem | Resolution |
|---|---|
| `Package 'cais_lab_robotics' not found` | Run `make bootstrap-gazebo`, then source `~/ros2_ws/install/setup.bash`. |
| A source change is not visible at runtime | Rebuild with `make bootstrap-gazebo` and open a newly sourced terminal. |
| `ModuleNotFoundError: rclpy._rclpy_pybind11` | Deactivate the Poetry virtual environment before running raw ROS2 commands. |
| `/ATTACHLINK` or `/DETACHLINK` is missing | Verify `linkattacher_msgs` and `ros2_linkattacher`, then rerun bootstrap. |
| Gazebo starts blank or slowly on WSL2 | Wait for software rendering or follow the WSL setup guide. |

For operation after installation, see
[ros2_operation_guide_dual_robots.md](docs/ros2_operation_guide_dual_robots.md)
and [ros2_three_mode_control_guide.md](docs/ros2_three_mode_control_guide.md).
